# Decision log

Record durable product, UX, architecture, privacy, identity, and release decisions here. Do not record speculative ideas as decisions.

| Date | Area | Decision | Reason | Status |
| --- | --- | --- | --- | --- |
| 2026-11-19 | Project | Start as a product-neutral Android workspace with no inherited app context | The future product is unrelated and not yet defined | Active |
| 2026-11-19 | Documentation | Preserve durable research, learnings, context changes, approvals, and rejections in repository Markdown; do not rely on chat history | Future work must remain grounded after context loss and across contributors | Active |
| 2026-11-19 | Open source | Maintain the project publicly at `github.com/chandsharma/kaju-goals`, accept community contributions, and license it under Apache-2.0 | The user explicitly requested an open-source, contribution-ready project; Apache-2.0 is Android-friendly and includes an explicit patent grant | Active |
| 2026-11-19 | Visual direction | Reject the warm bone, saturated ultramarine, chartreuse, apricot, and serif-led palette from concept v1 | The user found the colors weak and supplied a higher visual standard | Rejected |
| 2026-11-19 | Visual direction | Explore a cool-neutral, high-contrast, dimensional-bento system with one grotesk sans family, sculpted white surfaces, circular instruments, restrained semantic pastels, and soft directional depth | This captures the common qualities in the user's references while remaining original and implementable on Android | Active |
| 2026-11-19 | Visual direction | Approve concept v2 as the visual foundation, conditional on production usability, accessibility, and real-device validation | The user judged the second direction substantially stronger but explicitly required it to remain easy and intuitive | Active |
| 2026-11-19 | Primary job | Optimize first for personal goal tracking and progress recording, not coaching content, social features, or decorative analytics | The user expects to use the app mainly to track goals and progress | Active |
| 2026-11-19 | Information architecture | Use plain-language primary destinations: Today, Goals, Progress, and You; make the goal list a first-class view | Familiar labels and a persistent list reduce interpretation cost and support frequent tracking | Active |
| 2026-11-19 | Interaction | Make quick progress logging available from Today, the Goals list, and Goal detail, with the common case completed in no more than two deliberate actions | Frequent logging must feel faster than opening a spreadsheet or notes app | Active |
| 2026-11-19 | Identity | Use the product name **Kaju Goals** and application ID `com.chandsharma.kajugoals` | The user authorized development after this permanent identity was proposed; a new app requires a unique package identity | Active |
| 2026-11-19 | Platform | Set min SDK 26 and compile/target SDK 36 for the first implementation | This supports a broad modern Android baseline while using the installed current Play-compatible SDK | Active |
| 2026-11-19 | Architecture | Build the first slice with Kotlin, Compose, Material 3 foundations, Navigation 3, unidirectional ViewModel state, Hilt, Room, and coroutines/Flow | This is a maintainable production-oriented stack with explicit UI state and durable local data | Active |
| 2026-11-19 | Privacy | Keep the first slice local-first with no account, backend, analytics, ads, trackers, Internet permission, or sensitive runtime permission | Core personal tracking did not require external data collection before an owner-controlled sync boundary was approved | Superseded by optional Drive sync |
| 2026-11-19 | Data | Treat exact progress entries as authoritative and derive goal totals; store all authoritative values as integer `Long`s | Exact chronological records support correction, recovery, and deterministic calculations | Active |
| 2026-11-19 | Navigation | Maintain a separate saveable back stack for each top-level destination; hide top-level navigation during create/edit and detail flows | Users retain tab context while focused flows get maximum space and an unambiguous Back action | Active |
| 2026-11-19 | Safety | Require explicit confirmation before deleting a historical progress entry and offer immediate Undo after new logging | Progress history is user-created data and accidental loss must be recoverable or explicitly confirmed | Active |
| 2026-11-19 | Toolchain | Pin AGP 9.0.1, Gradle 9.1, Kotlin 2.3.20, Compose BOM 2026.03.01, and Navigation 3 1.2.1 until an API 37-capable stack is separately adopted | Newer indexed versions require unavailable API 37/newer AGP, and Navigation 3 1.2.2 was not present in Google Maven during setup | Active |
| 2026-11-19 | Testing | Use JUnit 4, fake-repository ViewModel tests, in-memory Room device tests, Compose behavior tests, and manual AVD screenshots for the first slice; defer automated preview screenshots | AGP 9.0 only supports the deprecated screenshot plugin, while the selected stable API 36 toolchain is otherwise verified | Active |
| 2026-11-19 | Release | Do not publish or begin Play Console release actions until the user explicitly confirms | The user explicitly prohibited Play publication at this stage | Active |
| 2026-11-19 | UX correction | Reject a create form that exposes title, metric, target, and unit as a visually equivalent stack of form controls | The user found it counterintuitive and work-like compared with the installed Goals app | Rejected |
| 2026-11-19 | Goal creation | Lead with one-tap fictional quick starts and large icon/symbol measurement cards; default new goals to Count; require only a name and metric-appropriate finish line; make Percentage and Done targets automatic | Common goals should be valid without typing, and unfamiliar measurement choices must be recognizable without reading documentation | Active |
| 2026-11-19 | Measurements | Support Count, Time, Percentage, Money, and Done with explicit `123`, clock, `%`, currency, and check symbols; include INR, USD, EUR, and GBP with INR as the default | Measurement meaning must be visible, and the owner specifically needs rupees | Active |
| 2026-11-19 | Money | Store all currency targets and progress in integer minor units and format them using the selected ISO currency, including Indian digit grouping for INR | Authoritative financial values must never depend on floating point and should read naturally | Active |
| 2026-11-19 | Quick logging | Use a metric-aware large decrement/increment stepper, three common shortcuts, optional collapsed note, and one explicit confirmation; keep the ordinary path at two actions from a visible goal | Logging is the dominant repeat task and must not feel like data entry | Active |
| 2026-11-19 | Goal list | Use compact scannable rows with a metric badge, exact current/target text, linear progress, one-tap `+`, and overflow actions | Progress must remain visible without spending a full card height on every goal | Active |
| 2026-11-19 | Motion | Override Navigation 3's 700 ms default with a restrained 160 ms enter / 90 ms exit fade | The user reported that smooth movement still felt slow; navigation should acknowledge state change without delaying work | Active |
| 2026-11-19 | Sync privacy | Add optional Google Drive `appDataFolder` sync using only `drive.appdata`; keep local use fully functional and never send goal data to a Kaju-controlled backend | The user requested recovery and cross-install continuity while keeping data in the user's own Google account | Active |
| 2026-11-19 | Sync identity | Use Google AuthorizationClient for short-lived Drive access; do not store access/refresh tokens or imply that the app knows the chosen email address | The scoped authorization result provides Drive access, not reliable account identity, and token custody should remain with Google Play services | Active |
| 2026-11-19 | Sync safety | Always download, validate, and merge before upload; merge stable record IDs by newest `(updatedAt, mutationId)`; sync deletion tombstones; apply the merge locally before any write; never create an empty cloud snapshot; retry conditional-write conflicts | A fresh empty install must restore existing cloud data and must never erase it; concurrent edits need deterministic, non-resurrecting behavior | Active |
| 2026-11-19 | Google Cloud | Use project `kaju-goals` with Drive API enabled, external OAuth in Testing, non-sensitive `drive.appdata`, and a debug Android client for `com.chandsharma.kajugoals.debug`; add the production package and Play App Signing certificate only during the approved release workflow | This enables safe development without prematurely publishing OAuth or Play configuration | Active |
| 2026-11-20 | Sync control | Let the user turn automatic Drive sync off without deleting either the local database or hidden Drive snapshot | Optional sync must remain reversible, while data deletion must never be implied by a connectivity toggle | Active |
| 2026-11-20 | Smart creation | Interpret ordinary goal titles locally and deterministically to suggest measurement, target, currency, and unit; keep every suggestion visible and editable; once the user manually changes an inferred field, manual input wins until `Apply suggestion` is chosen | Sentence-first creation removes setup work without making an opaque AI decision or sending private goal text off-device | Active |
| 2026-11-20 | Progress correction | Allow historical entries to be edited, backdated, added, subtracted, deleted, or expressed as a `Set total` correction while retaining exact entry history and sync mutation metadata | Personal records inevitably need correction, and totals must remain explainable and mergeable | Active |
| 2026-11-20 | Deadlines and pace | Make deadlines optional and show calm, quantitative pace guidance and remaining-per-week values; avoid punitive streak language | Time context makes goals actionable, but missed days should not make the product discouraging | Active |
| 2026-11-20 | Goal organization | Add search, optional categories, pinning, duplication/templates, and bulk archive as the list grows | The canonical list must stay fast and scannable beyond a handful of goals | Active |
| 2026-11-20 | Product roadmap | Approve reminders, milestones, weekly review, flexible recurring goals, exact charts, portable JSON/CSV, a home-screen widget, optional biometric lock, and optional attachments as staged production features | These additions can make the app exceptional, but each has distinct data, permission, sync, and verification requirements | Active |
| 2026-11-20 | Reminder platform | Use inexact scheduled work for ordinary reminders and request notification permission only when a user enables a reminder; do not request exact-alarm access | Exact timing is not the app's core function and Android explicitly discourages exact alarms for ordinary reminders | Active |
| 2026-11-24 | Creation disclosure | Keep a new goal to title plus a compact inferred summary in the ordinary path; reveal measurement controls for ambiguous titles or after `Edit`, and keep deadline/repeat/category behind `More options` | The common path should feel like naming a goal rather than completing a form | Active |
| 2026-11-24 | Manual inference control | Treat opening the inference editor or changing any measurement field as an explicit manual override; later title edits may show a new suggestion but never silently replace the manual choice until `Apply` is selected | Editable inference must remain predictable and user-owned | Active |
| 2026-11-24 | Recurring progress | Preserve all recurring progress history and calculate the current total from the active local daily, weekly, or monthly period rather than resetting or deleting records | Recurrence should be flexible and auditable without punitive streaks | Active |
| 2026-11-24 | Progress correction | Put the primary log confirmation above backdate and note options so the two-action common path remains immediately visible; retain Add, Subtract, Set total, entry edit, and deletion as traceable deltas | Correction must be powerful without making every routine check-in feel like data entry | Active |
| 2026-11-24 | Milestones and review | Use automatic 25/50/75/100 milestones and an exact seven-day check-in review for this slice; defer user-defined milestone editing until evidence shows it is needed | Automatic landmarks add motivation without adding creation work | Active |
| 2026-11-24 | Portable data | Provide a complete versioned JSON backup with merge-first restore plus spreadsheet-friendly CSV export through the system document picker | Users need an understandable recovery path independent of Google Drive and without broad storage permission | Active |
| 2026-11-24 | App lock | Make biometric/device-credential locking optional and local-only; do not sync the preference | Security policy belongs to the device and should not unexpectedly lock another installation | Active |
| 2026-11-24 | Widget | Use stable Glance 1.2 for a glanceable next-goal widget that opens the app; defer direct widget logging to a separately tested interaction | The installed API 36/AGP 9.0 toolchain supports the stable library, while direct mutation from a widget needs a clearer correction/undo path | Active |
| 2026-11-24 | Attachments | Defer attachments rather than storing local-only URIs or implying sync before byte storage, quotas, deletion, recovery, and cross-device semantics are defined | An incomplete attachment design would strand or silently lose private user data | Active |
| 2026-11-24 | Development version | Advance the installed development build to version code 2 / `0.2.0-dev` and update the physical Pixel in place with `adb install -r` | The new schema and interaction slice are a material, testable upgrade while Play publication remains deferred | Active |
